# Final pass

Конкретный чек-лист. Почему что-то из этого важно — в `SKILL.md`.

Прогоняй его перед тем, как назвать фазу или проект законченными, и перед любым
пушем, меняющим то, что видит посетитель. Сообщай, что нашёл, а не чини всё молча:
смена имени или перенос файла заметны, а заметные изменения — решение владельца.

---

## Посмотри так, как смотрит посторонний

Открой страницу репозитория и остановись. Прежде чем читать то, что ты и так
знаешь:

- [ ] Говорит ли первый экран, что это такое и что человек может с этим сделать?
- [ ] Есть ли ссылка на живую вещь, если она есть?
- [ ] Корень показывает блоки — или кучу файлов?
- [ ] Колонка коммитов читается предложениями — или как `wip` / `fix` / `update`?
- [ ] Есть ли здесь что-то очевидно оставшееся — черновик, черновой файл,
      `test2.py`, безымянный ноутбук?

## Корень

- [ ] Три обязательных документа на месте: `PROJECT_MEMORY.md`,
      `PROJECT_IDEAS.md`, `PROJECT_PHILOSOPHY.md`.
- [ ] В `PROJECT_PHILOSOPHY.md` есть блок «How to maintain», и он описывает
      актуальный порядок обновления проекта.
- [ ] `PROJECT_MEMORY.md` проходит свою проверку: свежая сессия, прочитав только
      его, восстанавливает контекст проекта целиком.
- [ ] Кроме них — только readme, лицензия и то, что платформа держит в корне
      принудительно. Всё сверх этого имеет указание автора.
- [ ] Любой другой файл живёт в блоке.
- [ ] Ничего не перенесено из того, что платформа закрепляет на месте
      (CI-директории, конфигурация хостинга, файл зависимостей).
- [ ] Имена согласованы — одно имя в нижнем регистре через дефис на вещь;
      машинерия остаётся в нижнем регистре или с точкой в начале.

## Проза

- [ ] Ни один счётчик, меняющийся при пересборке, не появляется в описании того,
      чем проект *является*.
- [ ] Каждое измерение, сохраняющее своё число, несёт свою дату или прогон.
- [ ] Никакие два документа не отвечают на один вопрос.
- [ ] Ни плана, ни открытых вопросов, ни очереди черновиков на титульной странице —
      рабочий материал сидит в одном рабочем файле.
- [ ] Первый абзац README был бы понятен тому, кто никогда не слышал о проекте.
- [ ] Ссылки разрешаются. Внутренние ссылки по-прежнему указывают на существующие
      файлы.

## Коммиты

- [ ] Заголовки — простые предложения, с заглавной, без точки в конце, без
      префиксов и кодов задач, желательно короче примерно пятидесяти знаков.
- [ ] Подробности в теле, а не втиснуты в заголовок.
- [ ] Ни один коммит не смешивает переформатирование со сменой смысла.
- [ ] Машинные коммиты подчиняются тому же правилу.

## Поверхность платформы

- [ ] Неиспользуемые вкладки и панели выключены (вики, проекты, пакеты, деплои).
- [ ] Описание заполнено.
- [ ] Ссылка на живую вещь проставлена.
- [ ] Темы проставлены.
- [ ] Релиз метит законченное состояние, если проект до него дошёл.
- [ ] Всё, что может сделать только владелец в интерфейсе, передано точными кликами
      и точным текстом для вставки.

## Гигиена

- [ ] Никаких секретов нигде — код, ноутбуки, примеры, история коммитов.
- [ ] Произведённые данные не удалены; датированные выгрузки сохранены как архив.
- [ ] Тесты и линтеры зелены на ветке, которую будут пушить.
- [ ] Ветка main равна тому, что задеплоено.
- [ ] Временных веток от рискованной работы не осталось.

---

## Как сообщать о найденном

Сортируй по тому, что посетитель заметит первым, а не по тому, что легче починить.
Протухшее число в README старше неопрятного имени папки тремя уровнями ниже,
потому что одно читают, а другое нет.

Явные ошибки чини и сообщай о них. Всё заметное — переименование, перенесённый
файл, другая формулировка в чём-то, что встречает читатель, — это предложение, а
не изменение.

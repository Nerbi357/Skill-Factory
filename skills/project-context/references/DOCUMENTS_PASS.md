# Documents pass

Конкретный чек-лист внутренности трёх рабочих документов. Почему что-то из этого
важно — в `SKILL.md`.

Прогоняй его в момент записи — когда кладёшь решение, принцип или идею, — и на
закрытии фазы. Правило, проверяемое только тогда, когда работу называют
законченной, нарушено всю фазу до этого.

---

## Философия

- [ ] В `PROJECT_PHILOSOPHY.md` есть блок «Как поддерживать», и он описывает
      актуальный порядок обновления проекта.
- [ ] В `PROJECT_PHILOSOPHY.md` есть блок «Как части соединены», и все связи
      между файлами названы только в нём.
- [ ] `PROJECT_PHILOSOPHY.md` понятен целиком без открытия других файлов: вне
      блока связей он не ссылается ни на репозиторий, ни на скилл, ни на агента,
      ни на соседний документ.
- [ ] Промптов, технических цифр и процедур в `PROJECT_PHILOSOPHY.md` нет — они
      в `PROJECT_MEMORY.md`.

## Память

- [ ] Рабочее соглашение с автором лежит в `PROJECT_MEMORY.md`, а не разнесено по
      скиллам.
- [ ] План в `PROJECT_MEMORY.md` ведётся фазами: у каждой цель, принятые решения
      с пояснением «почему», и шаги — только пока фаза не закрыта.
- [ ] `PROJECT_MEMORY.md` проходит свою проверку: свежая сессия, прочитав только
      его, восстанавливает контекст проекта целиком.

## Идеи

- [ ] `PROJECT_IDEAS.md` держит направления развития, а не план: то, что решено
      делать, живёт в `PROJECT_MEMORY.md`.

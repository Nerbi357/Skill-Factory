## Группы для решения владельца

Правило «две редакции, потому что два адресата» принято владельцем 2026-08-19 и
здесь не отменяется. По каждой группе два исхода: оставить редакции с проверкой
сходства по объявленным фразам или свести к одной.

**Д1 · Метод фаз: память ↔ `git-repo-structure` §2 ↔ философия «Как
поддерживать».** Двенадцать абзацев памяти (4, 6, 7, 8, 11, 12, 13, 15, 16, 18 и
их соседи) держат полный метод; скилл держит короткую форму для любого проекта;
философия — две строки порядка владельца. Найдено одно расхождение: цель фазы
(6). Варианты: А — три редакции остаются, проверка сходства по трём фразам («цель
фазы», «закрытая теряет шаги», «закрытая не переписывается»), расхождение по цели
чинится в скилле под редакцию памяти; Б — метод фаз уходит из скилла: §2 скилла
говорит только, что план ведётся фазами и что закрытая фаза не переписывается,
остальное — память; В — метод фаз уходит из памяти в скилл целиком. Рекомендация
сессии — А до шага 5.3: он решает, делится ли `git-repo-structure`, и
вторая половина скилла — устройство трёх документов — и есть дом этого метода;
В сейчас сделал бы скилл длиннее перед его разделением, Б оставил бы любой другой
проект без метода фаз.

**Д2 · Ветки: память ↔ `git-repo-structure` §7.** Скилл даёт общее правило и
отдаёт выбор владельцу; память записывает выбор. Варианты: А — оставить обе с
проверкой по фразе «рискованная работа получает временную ветку»; Б — в памяти
оставить только выбор проекта (`main` единственная; рабочая ветка живёт с фазой),
общую фразу о временной ветке снять. Рекомендация — Б: память держит своё, скилл
— общее, проверка не нужна.

**Д3 · Проводка: память ↔ `AGENT.md`.** Два адресата по решению 2026-08-19.
Варианты: А — оставить обе с проверкой по фразе «кто что читает: какой агент
какие скиллы потребляет»; Б — свести к одной. Рекомендация — А: папка агента
работает без памяти.

**Д4 · Формулировки: память ↔ `agent-readable`.** Отложено из 0.4. Варианты: А —
блок ужимается до одной строки-указателя на скилл плюс половина о границе
применения в этом проекте (витрина по `git-repo-structure`, идеи свободны от
ограничений длины); Б — оставить четыре абзаца с проверкой сходства.
Рекомендация — А: метод уже в скилле, три абзаца памяти — его копия.

**Д5 · Пересечение по вопросу: память ↔ `AGENT.md` (два места) ↔
`skill-anatomy`.** Варианты: А — оставить все с проверкой по фразе «по вопросу,
а не по событию» в памяти и агенте; Б — свести: в памяти одна строка «пересечение
судится по вопросу; правило — у агента и в `skill-anatomy`». Рекомендация — А:
адресатов три и папки работают порознь.

**Д6 · Реестр отклонённого: память ↔ философия ↔ `AGENT.md`.** Три адреса по
решению 0.5, каждый со своей ролью. Варианты: А — оставить с проверкой по фразе
«только с новым сигналом»; Б — свести. Рекомендация — А.

**Проверка сходства** — шаг 4 плана: отдельный скрипт `.claude/scripts/check_pairs.py`
с объявленным списком пар «файл · фраза»; красный, если фраза исчезла из любого
из названных файлов. Пары объявляются по ответам выше.

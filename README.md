# Skill Factory

**Библиотека методов, по которым ИИ-агент работает так, как нужно, — а не так, как
получится.**

Агент, которому дают задачу без правил, решает её заново каждый раз: заново
выбирает, что считать готовым, заново решает, что спросить, а что додумать. Здесь
эти правила записаны — по одному файлу на метод, — и любая сессия может их
прочитать и начать работать по ним.

**Скилл** — это записанный метод: правила о том, как делать определённую работу.
Сессия читает его и начинает работать иначе.
**Агент** — это работник со своим контекстом: ему делегируют задачу, он уходит и
возвращается с отчётом.

Разница в одной фразе: скилл меняет, *как* работа делается; агент меняет, *кто* её
делает.

### Скиллы

| | Что делает |
| --- | --- |
| [`agent-readable`](skills/agent-readable/) | Приводит служебный текст — файлы скиллов, агентов и их справочные файлы — к форме, в которой исполнитель читает его однозначно и не тратит контекст на то, что помогает только проверяющему, и доказывает списком указаний, что после правки текст велит делать то же самое. |
| [`confidence-check`](skills/confidence-check/) | Помечает каждый факт тем, насколько он на самом деле известен — проверено, видел, помню или вывел — и запрещает выдумывать конкретику. |

| [`signal-capture`](skills/signal-capture/) | Записывает наблюдения о том, как идёт работа, в файл SIGNALS.md, чтобы позже они улучшили библиотеку скиллов, а не забылись. |
| [`skill-anatomy`](skills/skill-anatomy/) | Определяет, как пишется скилл или агент этой библиотеки — четверо ворот перед первой строкой, пять тестов «скилл или агент», анатомия папки, frontmatter и тела, эвристики суждения о правке. |
| [`stress-run`](skills/stress-run/) | Проверяет готовый артефакт прогонами на выдуманном материале, устроенном как настоящий, и сводит результат в отчёт о том, что держится и что ломается. |
| [`verify-before-done`](skills/verify-before-done/) | Запрещает называть что-либо законченным без доказательства, что оно работает, и требует сначала намеренно попытаться это сломать. |

## Принципы в девяти строках

Полностью — в `PROJECT_PHILOSOPHY_CHECK.md`, а выбор между скиллом и агентом — в
`skills/skill-anatomy/`; здесь то, что стоит знать до того, как открыть хоть один
файл.

- Библиотека существует, чтобы снять необходимость объяснять одно и то же дважды.
  **Всё, что объяснено дважды, принадлежит скиллу.**
- **Скилл — вариант по умолчанию.** Агент оправдан только там, где изоляция,
  параллелизм, независимость, другой профиль прав или отдельный триггер и есть
  суть дела.
- **Каждая папка артефакта обязана работать в одиночку**, будучи отправленной в
  чат, где нет больше ничего.
- **Ничто не входит сюда без заявления о том, что́ меняется в поведении из-за
  него.**
- **Наблюдения собираются сырыми** и становятся изменениями только на разборе,
  где решает владелец. Решение принимается в разговоре; pull request его
  фиксирует.
- **Файлы не несут истории.** Чем вещь *является*, живёт в файле; что с ней
  *происходило* — в git.
- **Слабые скиллы сливаются с сильными или переписываются**, а не удаляются
  молча.
- **Всё, что нужно, чтобы понять, использовать или править библиотеку**, живёт в
  корневых файлах и папках артефактов — больше нигде.
- **Ничто из зоны разбора никогда не загружается в настоящую работу.**

## Что здесь лежит

| | |
| --- | --- |
| `skills/` | методы, применяемые в работе |
| `agents/` | работники со своим контекстом |
| `PROJECT_PHILOSOPHY_CHECK.md` | принципы, по которым живёт репозиторий, и карта того, как его части соединены |
| `PROJECT_MEMORY_CHECK.md` | полный контекст проекта: рабочее соглашение, план фазами, принятые решения |
| `PROJECT_IDEAS_CHECK.md` | направления развития — что улучшить, что добавить, куда расшириться |
| `SIGNALS.md` | журнал наблюдений о том, как шла работа; его ведёт скилл `signal-capture` |
| `.claude/` | хуки и скрипты, которыми репозиторий обслуживает сам себя |
| `.github/` | воркфлоу проверок, идущий на каждый пуш и pull request |
| `LICENSE` | MIT |
